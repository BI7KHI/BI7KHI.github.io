《自行车电控指南》续——从蓝牙抓包到自研控制台

2026年09月21日 技术 约3.5k字 预计需要13分钟

宇宙安全声明（续）

  • 接上回《自行车电控指南》，车还在，电控也没炸，安全第一依然要放在最前面。
  • 所有蓝牙、控制器、限速相关的调试只在封闭场地、抬起车轮、确认周围无人无车的情况下进行。
  • 本文只针对自有设备做互操作与协议研究，不分发任何厂商固件、闭源二进制或破解后的整包。
  • 强制超速是厂商调试接口，会绕过出厂限速。别在公共道路上学，别拿它当合法速度表。
  • 真要上路，请遵守当地对电动自行车速度、功率和改装的强制法规。

前情提要

上回把一辆山地车塞进了 48V 后驱电机、大疆 TB47/TB78 电池和恒泰普瑞（HTPR）控制器。车能跑，但有一件事一直很难受：

控制它的唯一入口是厂商的微信小程序。

小程序本身没毛病，能连、能看、能改参数，但它有三个致命问题：

  • 数据只能看，不能留存，没有历史曲线；
  • 没有原始帧、没有二次开发接口，想接自己的码表或 ESP32 只能干瞪眼；
  • 界面是官方定义的，想做一个竖屏仪表、GNSS 天空图或者自己的标定面板，基本不可能。

所以这次的目标很朴素：自己写一个手机控制面板，直连控制器，读电压 / 电流 / 转速 / 转把电压，并做有限的下发控制。

项目已经整理到：

  • GitHub：https://github.com/BI7KHI/htpr-ble-console.git
  • 本地代码：C:\Users\Admin\Desktop\htpr-ble-app
  • 协议文档：tools/PROTOCOL.md
  • Python 参考实现：tools/htpr_protocol.py

折腾路线总览

这次没有一上来就反编译，而是按“先能看到，再能看懂，最后能用”的顺序推进：

前两步解决“官方到底发了什么”，第三步解决“这些字节到底是什么意思”，最后一步才是写 App。

第一阶段：先把原始协议帧抓下来

控制器用的是 Nordic UART Service（NUS） 透传，这个在蓝牙调试助手里一眼就能看出来：

然后手动对照官方小程序里的操作：

  • 连接控制器；
  • 看实时数据页面；
  • 改一档限速；
  • 开关某个功能；
  • 断开重连。

在 Wireshark 里就能看到 notify 句柄上每 500 ms 左右来一次 67 字节，以及用户点按钮时从手机发往 write 句柄的写命令。

这个阶段解决的是“传输行为”问题：

  • 确认官方 App 和小程序确实走的就是 NUS；
  • 确认读帧和写帧的长度、速率、触发时机；
  • 确认下发命令也是 C9 9C 开头，但载荷已经过一层处理，不是肉眼可读的明文。

但 HCI 抓包只能看到“密文长什么样”，看不到“为什么这样加密”。要还原字段偏移，还得继续往下走。

第三阶段：微信小程序逆向解密

官方小程序包 id 此处做脱敏处理（wx0e****ee37），用 PC 微信打开并缓存后，可以得到 __APP__.wxapkg。

PC 微信的 wxapkg 不是老式明文包，而是 V1MMWX 加密格式。公开的解密流程大致是：

  • PBKDF2（salt = saltiest）派生密钥；
  • AES-CBC（iv = the iv: 16 bytes）解密；
  • 最后再按 ord(appid[-2]) 做一次单字节 XOR。

仓库里保留了参考脚本：

reverse/pc_wxapkg_decrypt_ref.py

解密并解包后，关键代码在模块路径 D:/wook/恒泰/utils/index.js 里。搜索 decrypt、encryption、ab2hex 这几个函数，整个协议的轮廓就出来了。

3.2 帧格式与字段映射

解密之后，协议就非常清楚了：

  • 校验：sum(bytes[0..64]) & 0xFF == bytes[65]；
  • 帧尾：bytes[66] == 0xCC；
  • 多字节字段按大端读取。

仪表帧 C9 9C 94 05：

字段 偏移 换算
电压 BE(63,64) / 100 → V
转把电压 BE(37,38) / 200 → V
功能设置字 BE(44,45) 16 bit，其中 bit9 = 强制超速
高速档限速 u8(51) motion3
车型 ID u8(48) —

遥测帧 CA AC 96 05：

字段 偏移 换算
电流 BE(19,20) / 10 → A
转速原始值 BE(21,22) × 20
显示转速 同上 floor(rotationalspeed / a)，本车型 a = 25
低速 / 中速档限速 u8(11) / u8(12) motion1 / motion2
转矩、限流环、运行状态等 略 见 tools/PROTOCOL.md

官方小程序里一共有 25 处 writeBLECharacteristicValue，主要命令包括：

  • c99c0002：写功能设置、锁车、码表等；
  • c99c0602：写三档限速、电流、运行模式等；
  • OTA 相关命令：9c9c...。

命令帧的构造套路也和抓包对上了：

  1. 以最近一帧仪表帧为模板，先解密；
  2. 改对应字节；
  3. 重算 byte[65] 校验；
  4. 整帧加密后 writeNoResponse。

协议对不对，不能只看代码，还得拿车和万用表验。四组工况的抓包结果如下：

第四阶段：把协议变成自己的控制台

协议搞明白之后，接下来就是产品化。

4.1 Python 参考实现

先写了零依赖的 tools/htpr_protocol.py，实现：

  • decrypt() / encrypt()；
  • checksum() / verify()；
  • parse_dashboard() / parse_realtime()；
  • build_command()。

再用 bleak 写了一个 PC 端 BLE 桥 tools/ble_bridge.py，配了一个 Flask 网页面板，可以实时看电压、转把、电流、转速和原始帧。没有设备的时候还能回放 tools/captures/ 里的抓包文件，方便联调前端。

4.2 Flutter 手机控制台

真正想要的是一个能放在车把上的手机仪表，所以最终用 Flutter 写了 Android 端 App。

主要功能：

  • BLE 直连：按 MAC 直连或按名称扫描，自动重连；
  • 半圆仪表：速度、电压、油门、电量、电流、功率；
  • 速度源徽标：实时标出当前速度来自 GNSS 还是 转速；
  • GNSS 天空图：Kotlin 侧用 GnssStatus.Callback 拿到每颗卫星的方位角 / 仰角 / 载噪比；
  • 行驶统计：本次 / 累计里程、最高 / 平均速度、运行时长、能耗、实时曲线；
  • 档位速览与强制超速开关：仪表页直接看三档限速值；
  • 参数标定：轮径、转速系数、速度微调、转把上下限、电池串数、单体截止电压；
  • 在线动态标定：用 GPS 作真值，过原点最小二乘拟合转速 → 时速系数。

4.3 为什么还要做 GNSS 融合

协议里确实有转速字段，但这个字段有个非常坑的固件行为：

松油门滑行时，控制器转速字段恒为 0。

不是解析错，官方小程序也一样。低速时还会因为霍尔计数窗口太短而间歇性掉零。

踩坑与经验总结

这次折腾的价值，其实不在“写了一个 App”，而在于把一个闭环走通了。总结几条经验：

  1. 先抓包，再逆向，别急着猜字段。
    没有动态抓包，静态代码里的偏移量很难确认；没有静态逆向，抓到的只是一堆密文。两者必须互证。

  2. 传输层和协议层要分开看。
    NUS 只是“管子”，67 字节帧才是“货物”。先确认 GATT 服务、特征值、读写方向，再谈帧格式。

  3. 不要假设“看起来像明文”的帧就是明文。
    C9 9C 帧早期被当成明文，导致电压、转把字段全部错位。后来才发现官方 ab2hex 对 c99c 和 caac 都调用了同一个 decrypt()。这是整个项目最大的一个坑。

  4. 校验和 + 帧尾是最可靠的验伪工具。
    只要 sum(bytes[0..64]) & 0xFF == bytes[65] 且 bytes[66] == 0xCC，基本就能确认解密正确。先让校验 100% 通过，再看字段。

  5. 一定要有真实物理量对照。
    万用表读数、转把电压、空载转速、负载电流，都是验证协议正确性的锚点。只靠“数值看起来合理”不够。

  6. 协议对，不代表固件行为对。
    转速在滑行时恒为 0 是控制器固件行为，官方小程序也这样。这种时候只能改软件策略，比如 GNSS 融合和在线标定，而不是怀疑自己的解析代码。

  7. 微信小程序版本会影响逆向流程。
    老版 wxapkg 可能直接解包，新版 V1MMWX 要走 PBKDF2 + AES-CBC + XOR。不同基础库、不同开发者工具版本导出的包也可能有差异，脚本要按实际包格式调整。

  8. 单连接限制要提前知道。
    NUS 模块同一时刻只允许一个中心设备连接。官方小程序连着时，自研 App 会连不上，不是代码问题，也不是蓝牙坏了。先在小程序里点断开。

  9. 安全和合规永远是第一位的。
    只碰自己的设备，只在封闭场地调试，不公开厂商固件，不提供 OTA 能力，不诱导别人上路飙车。强制超速这个功能，知道它存在就够了，别乱用。
